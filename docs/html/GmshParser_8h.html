Gmsh 4.1 MSH format parser for the CFEM++ solver.

  • ### MESH ARCHITECTURE & ENTITY STRATEGY This parser implements a strict decoupling between geometric data and computational semantics using a dual-layer entity system:
  • #### 1. Mandatory "Universe" Domain (ID -1)
  • The solver requires a Physical Group named **"Universe"** in the .msh file.
  • This entity must match the maximum dimension of the mesh (e.g., 3D for volumes).
  • Filtering: Elements not belonging to any Physical Group are ignored to ensure a clean computational domain.
  • #### 2. Automated System Boundary (ID -2)
  • After topological reconstruction (buildMesh), the parser identifies all facets without neighbors (exterior faces).
  • These facets are automatically stored in the **"SYS_BOUNDARY"** entity.
  • This ensures boundary coverage even if the user fails to tag surfaces in Gmsh.
  • #### 3. User-Defined Entities (ID > 0)
  • Other Physical Groups (e.g., "Inlet", "Steel_Region") are mapped to positive internal IDs.
  • Robust Matching: Uses a "Corner-only" vertex intersection logic. A facet is assigned to a group only if its primary geometric vertices (corners) are tagged, making it immune to diagonal flips or mismatched mid-side nodes in quadratic meshes.
  • ### OPTIMIZATION TECHNIQUES
  • Tag Interning: Multiple physical tags per element are reduced to a single integer index (tag_list_id) pointing to a persistent table in the Mesh class.
  • Vertex Harvesting: Each entity collects and unique-ifies its member vertices via a finalize() call, providing O(1) access to DoFs for Dirichlet conditions.
  • Memory Reservation: Pre-allocates vectors for nodes and elements based on Gmsh block headers to minimize reallocations.
